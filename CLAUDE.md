# Location King — правила работы над проектом

Общение и комментарии в коде — на русском. Имена переменных, функций и файлов —
на английском.

## Что это

Геогессер по спутниковым снимкам. Игроку показывают участок снимка, он ищет это
место на карте мира. Как устроена игра и API — в [README](README.md), как
разворачивается — в [docs/deployment.md](docs/deployment.md).

## Перед каждым коммитом

```bash
cd backend
ruff check .
ruff format --check .
pytest
```

CI выполняет то же самое и падает, если проверки не проходят или покрытие
опускается ниже 60%.

## Категорически нельзя

**Заглушки вместо реализации.** Никаких mock-классов, подменяющих зависимости
внутри прод-кода, никаких функций, возвращающих захардкоженные данные «пока
что». Если задачу нельзя выполнить — скажи прямо и остановись.

**Глушение ошибок.** Никаких `try/except` вокруг импортов, никаких
`except Exception: pass` и bare `except`. Ошибка должна падать там, где
произошла. Перехваченное исключение либо обрабатывается осмысленно, либо
перевыбрасывается через `raise ... from e`. Правила `E722` и `B904` включены в
линтере намеренно.

**Отключение кода комментированием.** Не нужен — удали, история есть в git.

**Тесты, которые не могут упасть.** Никаких `if response.status_code == 200:`
перед проверками. Ассерты безусловные.

**Отчёты о своей работе в репозитории.** Не создавай файлы вида `FIXES.md`,
`REPORT.md`, `test_something.html`. Результат работы — это диф.

**Секреты в коде.** Только через переменные окружения. Отсутствующий секрет
означает, что приложение падает на старте, а не работает с дефолтом: так
сделано с `JWT_SECRET`.

## Обязательно

**Логирование, а не print.** В бэкенде `logging`.

**Импорты наверху файла.** Локальные импорты внутри функций — только при
реальном цикле, с комментарием почему.

**Одна реализация на одну задачу.** Перед тем как написать функцию, проверь
grep'ом, нет ли её уже. Расстояния и очки — только `app/services/scoring.py`,
геометрия тайлов — только `app/utils/geo.py`, авторизация — только
`app/dependencies.py`.

**Новые зависимости — с согласования.**

**Миграции только вперёд.** Применённые ревизии Alembic не редактировать; они
выведены из-под ruff, чтобы форматтер их не трогал.

**Сервер авторитетен.** Клиенту не отправляется ничего, чего он не должен
знать: координаты цели до конца раунда, чужие сессии, номера тайлов. Валидация
и подсчёт очков — только на сервере. Это главное свойство игры, и оно
закреплено тестами в `backend/tests/test_anticheat.py`: любое изменение схем
ответа сверяй с ними.

## Структура бэкенда

```
backend/app/
  routers/    — только HTTP-слой: разбор запроса, вызов сервиса, ответ
  services/   — бизнес-логика
  models/     — модели SQLAlchemy
  schemas/    — схемы Pydantic
  utils/      — чистые функции без зависимостей от БД
```

Бизнес-логика в роутере — повод вынести её в сервис. Ошибки бизнес-логики —
исключения из `app/exceptions.py`; HTTP-коды им проставляет обработчик в
`main.py`, роутеры про это не думают.

## Структура фронтенда

Статика без сборки, модули ES. `js/api.js` — клиент API и токены, `js/map.js` —
карты OpenLayers, `js/game.js` — ход партии, `js/ui.js` — DOM, `js/app.js` —
вход и меню. Глобальных переменных нет.

Страница не делает ни одного запроса на сторонние домены: OpenLayers лежит в
`vendor/`, шрифты системные. Это условие строгой CSP в nginx — добавляя внешний
ресурс, придётся осознанно расширять политику.

Адрес API берётся из `window.__CONFIG__` (`config.js`), по умолчанию — тот же
origin. Захардкоженных адресов быть не должно.

## Если что-то непонятно

Два решения выглядят одинаково разумно — спроси, не выбирай молча. Нашёл
проблему за рамками текущей задачи — сообщи, но не чини в том же коммите.
