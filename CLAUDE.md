# Location King — правила работы над проектом

Общение и комментарии в коде — на русском. Имена переменных, функций и файлов —
на английском.

## Что это

Геогессер по спутниковым снимкам. Игроку показывают участок снимка, он ищет это
место на карте мира. Как устроена игра и API — в [README](README.md), как
разворачивается — в [docs/deployment.md](docs/deployment.md), как за ним
наблюдать — в [docs/monitoring.md](docs/monitoring.md). Как игра выглядит и
почему именно так — в [docs/design.md](docs/design.md): палитра, шкалы,
правила про телефон и голос интерфейса.

## Перед каждым коммитом

```bash
cd backend  && ruff check . && ruff format --check . && pytest
cd frontend && npm run lint && npm run build
```

Проверять нужно теми же версиями, что стоят в `requirements-dev.txt` и
`package-lock.json`, и теми же командами. Глобально установленный ruff другой
версии сортирует импорты иначе, а `python -m pytest` добавляет текущий каталог
в `sys.path`, чего консольный `pytest` не делает, — оба раза локально было
зелено, а CI падал.

CI выполняет то же самое и падает, если проверки не проходят или покрытие
бэкенда опускается ниже 85%.

## Категорически нельзя

**Заглушки вместо реализации.** Никаких mock-классов, подменяющих зависимости
внутри прод-кода, никаких функций, возвращающих захардкоженные данные «пока
что». Если задачу нельзя выполнить — скажи прямо и остановись.

**Глушение ошибок.** Никаких `try/except` вокруг импортов, никаких
`except Exception: pass` и bare `except`. Ошибка должна падать там, где
произошла. Перехваченное исключение либо обрабатывается осмысленно, либо
перевыбрасывается через `raise ... from e`. Правила `E722` и `B904` включены в
линтере намеренно.

**Отключение кода комментированием.** Не нужен — удали, история есть в git.

**Тесты, которые не могут упасть.** Никаких `if response.status_code == 200:`
перед проверками. Ассерты безусловные.

**Отчёты о своей работе в репозитории.** Не создавай файлы вида `FIXES.md`,
`REPORT.md`, `test_something.html`. Результат работы — это диф.

**Секреты в коде.** Только через переменные окружения. Отсутствующий секрет
означает, что приложение падает на старте, а не работает с дефолтом: так
сделано с `JWT_SECRET`.

## Обязательно

**Логирование, а не print.** В бэкенде `logging`.

**Импорты наверху файла.** Локальные импорты внутри функций — только при
реальном цикле, с комментарием почему.

**Одна реализация на одну задачу.** Перед тем как написать функцию, проверь
grep'ом, нет ли её уже. Расстояния и очки — только `app/services/scoring.py`,
геометрия тайлов — только `app/utils/geo.py`, авторизация — только
`app/dependencies.py`.

**Новые зависимости — с согласования.**

**Миграции только вперёд.** Применённые ревизии Alembic не редактировать; они
выведены из-под ruff, чтобы форматтер их не трогал.

**Сервер авторитетен.** Клиенту не отправляется ничего, чего он не должен
знать: координаты цели до конца раунда, чужие сессии, номера тайлов. Валидация
и подсчёт очков — только на сервере.

**Всё, что создаёт записи в базе, ограничено по частоте.** Лимиты собраны в
одну таблицу `RULES` в `app/services/rate_limit.py`. Добавляя эндпоинт, который
что-то пишет или ходит наружу, добавь ему лимит. Это главное свойство игры, и оно
закреплено тестами в `backend/tests/test_anticheat.py`: любое изменение схем
ответа сверяй с ними.

## Структура бэкенда

```
backend/app/
  routers/    — только HTTP-слой: разбор запроса, вызов сервиса, ответ
  services/   — бизнес-логика
  models/     — модели SQLAlchemy
  schemas/    — схемы Pydantic
  utils/      — чистые функции без зависимостей от БД
```

Бизнес-логика в роутере — повод вынести её в сервис. Ошибки бизнес-логики —
исключения из `app/exceptions.py`; HTTP-коды им проставляет обработчик в
`main.py`, роутеры про это не думают.

Текст ошибки не пишется строкой на месте: он лежит в `app/messages.py` и знает
оба языка сразу. На каком отвечать, решает обработчик по заголовку
`Accept-Language`; русский — язык по умолчанию, и он же уходит в журнал.
Названия стран — там же по смыслу, в `app/utils/country_names.py`: в базе
лежит русское имя, по которому каталог сходится с границами, а игроку страна
называется на его языке.

## Структура фронтенда

React 18 + TypeScript + Vite. Слои знают только про соседний снизу:

```
src/
  api/         транспорт: fetch, токены, типы ответов
  domain/      чистые функции форматирования и оценки, без React
  i18n/        словари интерфейса: ru.ts исходный, en.ts повторяет его
  map/         карты OpenLayers, каждая своим модулем
  state/       контекст авторизации и редьюсер партии
  components/  разметка, стили рядом в CSS-модулях
```

Компонент не ходит в fetch напрямую — только через `api/`. Логику, которую
можно посчитать без DOM, кладём в `domain/`.

## Два языка

Интерфейс говорит по-русски и по-английски. Русский исходный: `i18n/ru.ts` —
это и словарь, и тип. `i18n/en.ts` объявлен этим типом, поэтому пропущенный
ключ не собирается, а не превращается в пустое место на экране.

Текст в разметке не пишется строкой: компонент берёт его из `useText()`.
Числа, расстояния и даты — из `useFormats()`: разряды, дробные и единицы в
двух языках разные. Слова после числительного склеивать из кусков нельзя —
такая фраза целиком лежит в словаре функцией.

Названия мест, правовые документы и сообщения сервера пока только русские.
Язык хранится в браузере, а не в профиле: он свойство того, кто сейчас
смотрит на экран, и выбирается раньше, чем появляется учётная запись.

TypeScript в strict, плюс `noUncheckedIndexedAccess` и
`exactOptionalPropertyTypes`. `any` и `@ts-ignore` не используем; если тип
внешней библиотеки не сходится, приведение делается в одном месте с
комментарием почему.

Цвета, шрифты, размеры, отступы, радиусы, тени, длительности и слои — только
из `src/styles/tokens.css`. Захардкоженное значение в компоненте означает, что
токена не хватает: добавь токен. Шкалы и роли ступеней описаны в
[docs/design.md](docs/design.md), и перед тем как поставить размер «на глаз»,
загляни туда: промежуточных значений вроде `12.5px` быть не должно.

Акцент в интерфейсе один — янтарный. Мятный, коралловый и голубой не
украшения, а кодировка: хороший результат, ошибка и метка догадки на карте.
Дисплейный шрифт достаётся только знаку игры и заголовкам экранов.

Играют и с телефона: любой экран должен работать на 390 пикселях в ширину и
на планшете. Поведение, которое держится на наведении курсора, обязано иметь
второй путь — на телефоне наведения не существует, и карта догадки там
открывается нажатием. Такие правила пишутся через `@media (hover: hover) and
(pointer: fine)`, а не через ширину экрана: планшет с мышью бывает, узкий
десктоп тоже.

Страница не делает ни одного запроса на сторонние домены — это условие строгой
CSP в nginx. Шрифты поэтому лежат в `public/fonts` (подмножества под OFL,
подробности там же в README). Добавляя внешний ресурс, придётся осознанно
расширять политику.

Адрес API берётся из `window.__CONFIG__` (`public/config.js`), по умолчанию —
тот же origin. Захардкоженных адресов быть не должно.

## Если что-то непонятно

Два решения выглядят одинаково разумно — спроси, не выбирай молча. Нашёл
проблему за рамками текущей задачи — сообщи, но не чини в том же коммите.
